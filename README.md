# Лабораторная работа №2. Микросервисы и API Gateway

Проект микросервисной архитектуры интернет-магазина с сервисом авторизации, каталогом товаров, Service Discovery на базе HashiCorp Consul и API Gateway на базе Nginx.

## Архитектура системы

- **auth** (порт 5000 внутри сети) — сервис аутентификации на FastAPI. Реализует регистрацию, вход с выдачей JWT-токенов (хэширование паролей через passlib) и получение информации о текущем пользователе (`/me`).
- **catalog-1**, **catalog-2** (порт 5000 внутри сети) — два экземпляра сервиса каталога товаров на FastAPI. Реализуют полный CRUD для товаров. Работают с общей базой данных SQLite (`products.db`). В ответах возвращают имя инстанса (`INSTANCE_NAME`) для демонстрации балансировки.
- **consul** (порт 8500) — Service Discovery. Сервисы регистрируются в Consul при старте и удаляются при завершении. Доступен веб-интерфейс мониторинга.
- **nginx** (порт 80) — API Gateway. Единая точка входа. Выполняет маршрутизацию запросов `/auth/` и `/catalog/`, а также балансировку нагрузки между инстансами каталога по алгоритму Round-Robin.

## Требования для запуска

- Docker и Docker Compose
- (Опционально) Python 3.10+ для локального запуска без Docker

## Запуск в Docker

Запуск всех сервисов выполняется одной командой:

```bash
docker compose up --build
```

После запуска доступны следующие адреса:
- API Gateway: `http://localhost:80`
- Веб-интерфейс Consul: `http://localhost:8500`

Для остановки:
```bash
docker compose down
```

## Локальный запуск (без Docker)

1. Установка зависимостей:
```bash
pip install -r requirements.txt
```

2. Запуск сервисов и локального шлюза:
```bash
python run_local.py
```

3. Запуск автотестов:
```bash
python test_all.py
```

## Основные эндпоинты

### Аутентификация (`/auth`)
- `POST /auth/register` — регистрация нового пользователя
- `POST /auth/login` — вход в систему и получение JWT-токена
- `GET /auth/me` — защищенный эндпоинт (требуется заголовок `Authorization: Bearer <token>`)

### Каталог товаров (`/catalog`)
- `GET /catalog/products` — список всех товаров (возвращает `instance_id`)
- `GET /catalog/products/{id}` — получение товара по ID
- `POST /catalog/products` — добавление нового товара
- `PUT /catalog/products/{id}` — обновление товара
- `DELETE /catalog/products/{id}` — удаление товара

## Проверка отказоустойчивости

В Nginx настроена директива `proxy_next_upstream`. При отключении одного из инстансов каталога:

```bash
docker stop catalog-1
```

Все входящие запросы автоматически перенаправляются на работающий `catalog-2` без ошибок для клиента.
